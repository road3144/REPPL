## 1. 브랜치 전략

인공지능 영상 특화프로젝트는 **Git Flow** 기반의 브랜치 전략을 사용합니다.

### 1.1 기본 브랜치 구조

```
master          ← 최종 배포 (직접 작업 금지)
  │
  └── dev       ← 개발 통합 브랜치
        │
        ├── fe/기능명    ← 프론트엔드 기능 브랜치
        ├── be/기능명    ← 백엔드 기능 브랜치
        ├── ai/기능명    ← AI 기능 브랜치
        └── data/기능명  ← 데이터 전처리 및 수집
```

| 브랜치 | 용도 |
|--------|------|
| `master` | 최종 배포 기준 (직접 작업 금지) |
| `develop` | 모든 기능이 병합되는 통합 개발 브랜치 |
| `fe/*`, `be/*`, `ai/*`, `data/*` | 각 파트별 기능 브랜치 |

### 1.2 기능 브랜치 규칙

**형식:** `파트/기능명` 또는 `파트/타입-기능명`

```bash
# 예시
fe/login-page              # 프론트엔드 로그인 페이지
fe/fix-header-bug          # 프론트엔드 헤더 버그 수정
be/auth-api                # 백엔드 인증 API
be/fix-token-refresh       # 백엔드 토큰 갱신 수정
ai/object-detection        # AI 객체 탐지 모델
ai/video-classification    # AI 영상 분류
data/annotation-pipeline   # 데이터 어노테이션 파이프라인
data/augmentation          # 데이터 증강 스크립트
```

| 파트 접두사 | 설명 |
|-------------|------|
| `fe/` | Frontend (프론트엔드) |
| `be/` | Backend (백엔드) |
| `ai/` | AI (모델 학습, 추론, 영상 처리) |
| `data/` | Data (데이터셋 가공, 증강, 어노테이션 관리) |

> 모든 기능 브랜치는 **develop 브랜치에서 분기**합니다.

## 2. 개발 환경 세팅

### 2.1 저장소 클론 및 브랜치 설정

#### Step 1: 저장소 클론

```bash
git clone <REPO_URL>
cd <REPO_NAME>
git checkout dev
```

#### Step 2: develop 브랜치 체크아웃

```bash
git checkout develop
git pull origin develop
```

#### Step 3: 기능 브랜치 생성

```bash
# 프론트엔드 기능 개발
git checkout -b fe/login-page

# 백엔드 기능 개발
git checkout -b be/auth-api

# AI 기능 개발
git checkout -b ai/object-detection

# 데이터 관련 작업
git checkout -b data/annotation-pipeline
```

### 2.2 파트별 의존성 설치

#### Frontend (폴더명: `frontend`)

```bash
cd frontend
npm install
npm run dev
```

#### Backend (폴더명: `backend`)

```bash
cd backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

#### AI (폴더명: `ai`)

```bash
cd ai
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

#### Data (폴더명: `data`)

```bash
cd data
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 3. 개발 워크플로우

### 3.1 전체 흐름도

```
1. develop 브랜치 최신화
      ↓
2. 기능 브랜치 생성 (fe/xxx, be/xxx 등)
      ↓
3. 개발 & 커밋
      ↓
4. 기능 브랜치 푸시
      ↓
5. MR(PR) 생성 (기능 브랜치 → develop)
      ↓
6. 코드 리뷰 & Approve
      ↓
7. 머지 완료 → 기능 브랜치 삭제
```

### 3.2 상세 단계

#### Step 1: 최신 코드 동기화

```bash
git checkout develop
git pull origin develop
```

#### Step 2: 기능 브랜치 생성

```bash
git checkout -b fe/login-page
```

#### Step 3: 개발 & 커밋

```bash
# 변경사항 확인
git status

# 스테이징
git add .

# 커밋 (컨벤션 준수)
git commit -m "[FE] feat: 로그인 페이지 구현"
```

#### Step 4: 기능 브랜치 푸시

```bash
git push origin fe/login-page
```

#### Step 5: MR(PR) 생성

- GitLab/GitHub에서 MR(PR) 생성
- 대상: `fe/login-page` → `develop`

#### Step 6: 머지 후 정리

```bash
# develop 최신화
git checkout develop
git pull origin develop

# 로컬 기능 브랜치 삭제
git branch -d fe/login-page
```

## 4. 커밋 컨벤션

### 4.1 커밋 메시지 형식

```
[파트] type: 설명
```

### 4.2 파트 코드

| 파트 코드 | 설명 |
|-----------|------|
| `FE` | Frontend |
| `BE` | Backend |
| `AI` | AI (모델 학습, 추론, 영상 처리) |
| `DATA` | Data (데이터셋 가공, 전처리) |
| `DOCS` | 문서 |
| `CHORE` | 설정/기타 |

### 4.3 Type 종류

| Type | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (README 등) |
| `refactor` | 코드 리팩토링 (기능 변경 없이 코드 개선) |
| `chore` | 설정, 빌드, 패키지 등 기타 작업 |
| `style` | 코드 포맷팅, 세미콜론 누락 등 |
| `test` | 테스트 코드 추가/수정 |

### 4.4 커밋 예시

```bash
# 좋은 예시
git commit -m "[FE] feat: 로그인 페이지 구현"
git commit -m "[BE] fix: 토큰 만료 처리 수정"
git commit -m "[AI] feat: YOLOv8 객체 탐지 모델 추가"
git commit -m "[AI] feat: 영상 분류 추론 파이프라인 구현"
git commit -m "[DATA] feat: 어노테이션 변환 스크립트 추가"
git commit -m "[DOCS] docs: README 업데이트"
git commit -m "[BE] refactor: 인증 로직 분리"

# 나쁜 예시
git commit -m "로그인 구현"           # 파트, type 없음
git commit -m "[FE] 로그인 구현"      # type 없음
git commit -m "feat: 로그인 구현"     # 파트 없음
```

## 5. MR(PR) 및 머지 규칙

### 5.1 MR(PR) 제목 형식

```
[파트] type: 작업 내용
```

**예시:**

```
[FE] feat: 로그인/회원가입 페이지 구현
[BE] fix: 토큰 갱신 로직 수정
[AI] feat: 객체 탐지 모델 통합
[DATA] feat: 학습 데이터 전처리 파이프라인 구현
```

### 5.2 MR(PR) 병합 규칙

| 규칙 | 설명 |
|------|------|
| Approve | **최소 1명 이상** 코드 리뷰 승인 필요 |
| Conflict | 충돌 해결 후 MR 요청 |
| Self-review | MR 생성 전 본인 코드 리뷰 필수 |

### 5.3 병합 흐름

```
기능 브랜치 → develop → master
```

**예시:**

```
fe/login-page → develop → master
be/auth-api → develop → master
ai/object-detection → develop → master
```

### 5.4 머지 후 브랜치 삭제 규칙

| 브랜치 유형 | 예시 | 머지 후 삭제 |
|-------------|------|--------------|
| **메인 브랜치** | `master`, `develop` | ❌ 삭제 안 함 |
| **기능 브랜치** | `fe/login`, `be/auth-api`, `ai/detection` | ✅ 삭제 |

```bash
# 기능 브랜치 머지 후 삭제 방법

# 로컬 브랜치 삭제
git branch -d fe/login-page

# 원격 브랜치 삭제
git push origin --delete fe/login-page
```

## 6. 주의사항

### 6.1 절대 금지 사항

| 금지 | 이유 |
|------|------|
| `master`, `develop`에 직접 push | 코드 품질 관리 |
| API Key, Token 등 민감 정보 커밋 | 보안 |
| `node_modules`, `.venv`, `dist` 커밋 | 저장소 용량 |
| 대용량 모델 파일(`.pt`, `.onnx` 등)을 LFS 없이 커밋 | 저장소 용량 초과 |

```gitignore
# Dependencies
node_modules/
.venv/

# Build

build/
__pycache__/
*.pyc

# Environment
.env
.env.local

# Logs
*.log

# IDE
.vscode/
.idea/

# AI 대용량 파일 (Git LFS로 관리)
# *.pt
# *.pth
# *.onnx
# *.tflite
# *.h5
```

## 7. 부록: 대용량 파일 관리 (Git LFS)

AI 영상 프로젝트에서는 학습된 모델 가중치, 대용량 데이터셋 등 큰 파일을 다루게 됩니다.  
이러한 파일은 **Git LFS (Large File Storage)** 를 사용하여 관리합니다.

### 7.1 Git LFS 설치 및 초기화

```bash
# Git LFS 설치 (최초 1회)
git lfs install

# 프로젝트에서 LFS 추적할 파일 형식 지정
git lfs track "*.pt"       # PyTorch 모델
git lfs track "*.pth"      # PyTorch 체크포인트
git lfs track "*.onnx"     # ONNX 모델
git lfs track "*.tflite"   # TFLite 모델
git lfs track "*.h5"       # Keras/TF 모델
git lfs track "*.weights"  # Darknet 가중치

# .gitattributes 파일이 자동 생성됨 → 반드시 커밋
git add .gitattributes
git commit -m "[CHORE] chore: Git LFS 트래킹 설정 추가"
```

### 7.2 LFS 파일 커밋 및 푸시

```bash
# 모델 파일 추가
git add ai/models/best.pt
git commit -m "[AI] feat: YOLOv8 학습 완료 모델 추가"
git push origin ai/object-detection
```

### 7.3 LFS 관리 파일 확인

```bash
# 현재 LFS로 추적 중인 파일 목록
git lfs ls-files

# LFS 트래킹 패턴 확인
git lfs track
```

### 7.4 주의사항

| 항목 | 설명 |
|------|------|
| `.gitattributes` 커밋 | LFS 설정 파일이므로 **반드시 커밋**해야 함 |
| GitLab LFS 용량 제한 | SSAFY GitLab 기준 LFS 용량 제한을 확인할 것 |
| 대용량 데이터셋 | 가급적 외부 스토리지(Google Drive 등) 활용 권장 |
| 모델 버전 관리 | 모델 파일명에 버전/날짜를 포함하여 관리 (예: `best_v2_0213.pt`) |

## 브랜치 명령어 정리

| 명령어 | 설명 |
|--------|------|
| `git checkout <브랜치>` | 기존 브랜치로 이동 |
| `git checkout -b <브랜치>` | 새 브랜치 생성 + 이동 |
| `git branch` | 로컬 브랜치 목록 |
| `git branch -a` | 모든 브랜치 목록 (원격 포함) |
| `git branch -d <브랜치>` | 로컬 브랜치 삭제 |
| `git push origin --delete <브랜치>` | 원격 브랜치 삭제 |
