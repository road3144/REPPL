# RePPL 프로젝트 빌드 및 배포 가이드

## 1. 프로젝트 개요

**RePPL** (Re-PPL) — AI 기반 영상 PPL(Product Placement) 합성 플랫폼

사용자가 원본 영상과 제품 이미지를 업로드하면, AI가 영상 속 적절한 위치에 제품을 자연스럽게 합성해주는 서비스입니다.

### 아키텍처 구성

```
┌──────────┐      ┌──────────────┐      ┌──────────────┐
│ Frontend │◄────►│    Nginx      │◄────►│   Backend    │
│ (React)  │      │ (Reverse     │      │ (Spring Boot)│
│ Vite+TS  │      │  Proxy+SSL)  │      │   Java 21    │
└──────────┘      └──────────────┘      └──────┬───────┘
                                               │
                  ┌─────────┐    ┌─────────┐   │
                  │  Redis  │◄──►│  Kafka   │◄──┘
                  │ (Session │    │(메시지큐)│
                  │  Store)  │    └────┬────┘
                  └─────────┘         │
                                ┌─────▼─────┐
                                │  AI Worker │
                                │ (Python)   │
                                │ GPU 서버    │
                                └────────────┘
                                      │
                                ┌─────▼─────┐
                                │  AWS S3    │
                                │ (파일저장) │
                                └────────────┘
```

## 4. 배포 방법

### 4-1. EC2 초기 설정

```bash
# EC2에 Docker 설치
ssh -i J14A401T.pem ubuntu@<EC2_IP> "bash -s" < scripts/ec2-setup.sh
```

### 4-2. Docker 이미지 빌드 및 푸시

```bash
# Backend 빌드
docker build -t <DOCKER_HUB_USER>/reppl-backend:latest ./backend

# Frontend 빌드
docker build --build-arg VITE_API_TARGET=https://<EC2_HOST> \
  -t <DOCKER_HUB_USER>/reppl-frontend:latest ./frontend

# Docker Hub 푸시
docker login -u <DOCKER_HUB_USER> -p <DOCKER_HUB_PASSWORD>
docker push <DOCKER_HUB_USER>/reppl-backend:latest
docker push <DOCKER_HUB_USER>/reppl-frontend:latest
```

### 4-3. EC2에서 서비스 실행

```bash
# EC2 접속 후
cd ~/app

# .env 파일 배치 (위 3-2 참고)
# docker-compose.yml, nginx/nginx.conf 배치

# SSL 인증서 볼륨 생성 (최초 1회)
docker volume create certbot_www
docker volume create certbot_conf

# 인프라 먼저 실행
docker compose up -d redis zookeeper kafka

# 앱 서비스 실행
docker compose pull backend frontend
docker compose up -d --no-deps backend frontend certbot

# Nginx 실행 (backend 준비 후)
docker restart nginx
```

### 4-4. AI Worker 실행 (GPU 서버)

```bash
cd ai
source venv/bin/activate

# Worker 백그라운드 실행
nohup python worker.py > worker.log 2>&1 &

# 밀린 메시지 스킵 후 실행
FLUSH_KAFKA=1 nohup python worker.py > worker.log 2>&1 &
```

### 4-5. GitLab CI/CD 자동 배포

`master` 브랜치에 push 시 `.gitlab-ci.yml`에 의해 자동으로:
1. Backend/Frontend Docker 이미지 빌드
2. Docker Hub에 push
3. EC2에서 이미지 pull 및 컨테이너 재시작

## 5. 배포 시 특이사항

### 5-1. SSL 인증서

- Let's Encrypt를 사용하며, `certbot` 컨테이너가 12시간마다 자동 갱신합니다.
- **최초 배포 시** 인증서가 없으면 Nginx가 시작되지 않을 수 있습니다. 수동으로 certbot을 실행하여 인증서를 발급받아야 합니다.

### 5-2. Kafka 외부 접근

- Kafka는 **포트 80**으로 외부 노출됩니다 (GPU 서버에서 접근용).
- EC2 보안 그룹에서 **포트 80, 443**을 열어야 합니다.
- `KAFKA_ADVERTISED_LISTENERS`의 `PLAINTEXT_HOST`가 `${EC2_HOST}:80`으로 설정되어, GPU 서버(AI Worker)가 EC2의 Kafka에 접근합니다.

### 5-3. AI Worker (GPU 서버)

- AI Worker는 **Docker 외부**에서 별도 GPU 서버에서 실행됩니다.
- **최소 GPU VRAM 8GB** 필요 (SAM `vit_h` 사용 시)
- **최소 시스템 메모리 16GB**, 권장 32GB
- NVIDIA CUDA 12.1 환경 필요
- Worker는 Kafka를 통해 EC2의 Backend와 통신합니다.

### 5-4. 파일 업로드 제한

- Nginx에서 `client_max_body_size 500M` 설정 (영상 업로드 고려)
- API 프록시 타임아웃: `proxy_read_timeout 300s`
- WebSocket 타임아웃: `proxy_read_timeout 86400s`

### 5-5. 정적 영상 파일

- 랜딩 페이지 배경 영상은 EC2의 `/home/ubuntu/static/videos/` 경로에 수동으로 배치해야 합니다.
- Frontend 컨테이너에서 해당 경로가 `/usr/share/nginx/html/videos`로 마운트됩니다.

### 5-6. 세션 관리

- Spring Session은 Redis를 사용하며, 세션 타임아웃은 `86400s` (24시간)입니다.

## 6. 주요 계정 및 프로퍼티 파일 목록

### 6-1. 프로퍼티 파일

| 파일 경로 | 설명 | 주요 설정 |
|-----------|------|-----------|
| `backend/src/main/resources/application.yml` | Spring Boot 설정 | Redis, Kafka, AWS S3 접속정보 (환경변수 참조) |
| `ai/config.py` | AI 서버 설정 | Kafka, GMS API, AWS S3 접속정보 (환경변수/`.env` 참조) |
| `ai/.env` | AI 서버 환경변수 | Kafka, Gemini API, AWS S3 키 (gitignore 대상) |
| `docker-compose.yml` | Docker 서비스 설정 | 전체 서비스 구성, 포트 매핑, 환경변수 |
| `.env` (프로젝트 루트) | Docker Compose 환경변수 | Docker Hub, EC2 호스트, AWS 키 (gitignore 대상) |
| `nginx/nginx.conf` | Nginx 리버스 프록시 | SSL, 프록시 설정, WebSocket |
| `frontend/vite.config.ts` | Vite 개발 서버 설정 | API 프록시 대상 (`VITE_API_TARGET`) |

### 6-2. 주요 접속 정보 (환경변수)

| 환경변수 | 용도 | 설정 위치 |
|----------|------|-----------|
| `REDIS_HOST` / `REDIS_PORT` | Redis 접속 | `docker-compose.yml` → Backend |
| `KAFKA_BOOTSTRAP_SERVERS` | Kafka 접속 | `docker-compose.yml` (Backend), `ai/.env` (AI) |
| `AWS_ACCESS_KEY` / `AWS_SECRET_KEY` | AWS S3 인증 | `.env` → Backend, `ai/.env` → AI |
| `AWS_REGION` / `AWS_S3_BUCKET` | AWS S3 리전/버킷 | `.env` → Backend, `ai/.env` → AI |
| `EC2_HOST` | EC2 도메인 | `.env` → Nginx, Kafka |
| `GMS_API_KEY` | GMS Gemini Flash API | `ai/.env` → 프롬프트 검증 |
| `GEMINI_API_KEY` | Gemini Image API | `ai/.env` → 이미지 생성 |
| `GOOGLE_CLOUD_PROJECT` | Vertex AI 프로젝트 | `ai/.env` → Gemini Vertex AI 모드 |

### 6-3. DB 정보

- **본 프로젝트는 RDB(MySQL, PostgreSQL 등)를 사용하지 않습니다.**
- 데이터 저장소:
  - **Redis**: 세션 관리 및 작업 상태 저장 (Key-Value)
  - **AWS S3**: 영상, 이미지, 결과물 파일 저장 (Object Storage)
  - **Kafka**: 작업 요청/진행률 메시지 전달 (Message Queue)
- ERD 없음 (RDB 미사용)
